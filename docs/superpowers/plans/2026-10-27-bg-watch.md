# bg-watch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `bg-watch` skill: it finds background sessions stuck on an `API Error`, restarts them, sends `retry`, and records each jag decision.

**Architecture:** Port the reference in `bg-watch/` (repo root of the main checkout, not tracked) to `skills/bg-watch/`. `build_info.py` reads the logs and writes facts. `run.py` asks jag, restarts, keeps the history and the jag log, and prints the report. `SKILL.md` holds the three modes and sends `retry` with SendMessage.

**Tech Stack:** Python 3 standard library, bash tests with fake `claude` and `jag` commands on `PATH`.

**Spec:** `docs/superpowers/specs/2026-10-27-bg-watch-design.md`

## Global Constraints

- Skill name `bg-watch`; schedule prompt `/bg-watch check`; default interval `5m`.
- State folder `~/.claude/bg-watch/`, changed by `BG_WATCH_STATE`.
- Never call `claude rm`. Never restart a session with `status == "busy"`. Skip the session whose ID is the basename of `$CLAUDE_JOB_DIR`.
- jag: `jag --json --max-chars 8000 --ask "<question>" SESSION <file>`; on exit 3–6, `jag --json --max-chars 8000 -F stuck=true <file>`; if `jag` is not on `PATH`, use the script's own flag. Never run `jag --check` or `jag --setup`. Never read `~/.config/jag/`.
- jag decides. The script's flag is only for comparison.
- Prose in ASD-STE100 Simplified Technical English.

## Review Focus

1. jag prints something that is not JSON (crash, empty output): the check must not crash; it logs the raw text and restarts nothing. Test in Task 2.
2. A session in the history that `claude agents --all` no longer lists: it is removed from the history. Test in Task 2.
3. A stuck session that is `busy`: it shows `STUCK (+1), skipped (busy)` and gets no `stop`/`respawn`. Test in Task 2.
4. A log where the `API Error` is followed only by spinner lines, `❯` prompts, or "needs input": still stuck. Test in Task 1.
5. Two checks in a row: the input files and the log lines add up, and the input folder keeps at most 500 files. Test in Task 2.

### Task 2: run.py

**Files:**
- Create: `skills/bg-watch/scripts/run.py` (from the reference `run.py`)
- Test: `skills/bg-watch/tests/bg-watch.test.sh`

**Interfaces:**
- Consumes: Task 1 files.
- Produces on stdout: a first line `jag mode: <mode> | exit <n> | stuck: <n>`; if `--ask` gave an `error` object, the lines `jag error cause: …` and `jag error fix: …`; a `jag disagrees:` line with the IDs (or `none`); the Markdown table `| Session | Name | Total failures seen | Status now |`; and the last line `RETRY_TO: <json list of names>`.
- Produces on disk: `$STATE/jag-input/<UTC %Y%m%dT%H%M%S.%fZ>.txt` (the newest 500 are kept); one line per check in `$STATE/jag-log.jsonl` with the keys `at, mode, cmd, exit, seconds, input, output, flag_stuck, jag_stuck, disagree`. `output` is the parsed JSON, or the raw text if it does not parse. `disagree` is the sorted symmetric difference of `flag_stuck` and `jag_stuck`.
- Status texts: `STUCK (+1), restarted: <state>`, `STUCK (+1), skipped (busy)`, `recovered`, `recovered (not in log window)`.

- [ ] **Step 1: Add the test cases:**
  - default jag: `claude stop s-stuck` and `claude respawn s-stuck` in `$CALLS`; no `stop`/`respawn` for `s-busy`; table has `STUCK (+1), skipped (busy)` for `s-busy`; `RETRY_TO` has the name of `s-stuck` only; no line in `$CALLS` starts with `claude rm`.
  - jag leaves out `s-stuck` (`FAKE_JAG_OUT` with no results): nothing restarted; log line `disagree == ["s-stuck"]`; stdout `jag disagrees: s-stuck`.
  - `FAKE_JAG_EXIT=4` with an `error` object: the `-F stuck=true` call follows; mode `jag free mode (--ask failed)`; stdout has `jag error cause:`.
  - `jag` not on `PATH`: mode `built-in stuck flag (jag not installed)`; `s-stuck` restarted.
  - jag prints `not json`: exit 0; nothing restarted; log `output == "not json"`.
  - history holds an ID `gone` that `agents.json` does not list: after the check, `gone` is not in `failure-history.json`.
  - two checks: two log lines, two input files.
- [ ] **Step 2: Run the test.** Expected: the new cases FAIL.
- [ ] **Step 3: Port `run.py`** (skip jag when no session has an `API Error`; mode `no session with an API Error`) with the default state folder, the jag log, the input files, the status texts, the history pruning, and safe JSON parsing.
- [ ] **Step 4: Run the test.** Expected: PASS for all cases.
